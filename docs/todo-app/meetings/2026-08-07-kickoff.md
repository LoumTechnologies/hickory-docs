# Todo app — kickoff, 7 Aug 2026

Raw notes. This is the top of the chain: everything downstream reaches these
decisions by reference, so a decision is written down exactly once and the
documents that depend on it fail when it changes.

Present: Nate. Notes taken live.

## What we're building

A todo app. Deliberately small — it exists to exercise the whole lifecycle,
meeting through shipped code, not to be a product.

## Decisions

Pasted back into these notes deliberately. `hick:copy` blocks are EXTRACTED,
not rendered — without this the notes weave to an empty section, and the one
document where a decision is actually written down becomes the one document
you cannot read it in. It also makes this document's own drift check
meaningful: change a decision and these notes go stale too, not just the
documents downstream.

<hick:paste select=".decision" />

<hick:copy id="d-storage" class="decision">
Tasks persist to a single JSON file on disk. No database. The app must run
with no service dependencies, because the point is to exercise the document
chain, not an install.
</hick:copy>

<hick:copy id="d-states" class="decision">
A task is in exactly one of four states: **open**, **blocked**, **done**, or
**dropped**. Blocked means work cannot proceed until something external
changes; it is not done and not dropped. Dropped is not deleted — it stays
in the file and stays listable, because "what did we decide not to do" is
the question people actually come back for.
</hick:copy>

<hick:copy id="d-identity" class="decision">
Tasks are identified by a short opaque id assigned on creation, never by
their title. Titles are editable; anything that references a task must
survive a retitle.
</hick:copy>

<hick:copy id="d-interface" class="decision">
The interface is a CLI. No web UI in the first cut — a UI would double the
surface without exercising any part of the lifecycle that the CLI does not.
</hick:copy>

## Open questions

Not decisions yet, deliberately left loose:

- Does a task need a due date? Nobody argued for it. Left out.
- Sub-tasks? Same. If it comes up twice, it becomes a decision.

## Not discussed

Multi-user, sync, auth. Out of scope for the first cut.
