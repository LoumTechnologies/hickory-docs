# A Refactor Records What It Moved — Byte-Exactly, And Only When Continuity Is On

Given a pinned refactor baseline, when the baseline is ended and the
restructured document still produces byte-identical outputs, then every span
that moved is recorded in the correspondence journal as a **byte-precise**
fact; and when continuity is off for the project, then nothing is recorded
anywhere.

Refactor mode is a machine for destroying textual continuity while
guaranteeing semantic identity: pin a baseline, restructure the document, and
`compare_outputs` proves the generated bytes unchanged — while blame afterwards
says every line is new. That is the one case where git's line-based correlation
is not merely weak but wrong, and this product creates it deliberately.

**The mechanism is free, because the work is already done.** The outputs are
proven identical, which makes them a **join key**: an output byte maps through
lineage to a span in the baseline document *and* to a span in the restructured
one, and composing the two gives the old-span → new-span correspondence
exactly, with no identity scheme involved.

Corollaries that are part of the guarantee:

- **Only when the outputs still match.** A restructure that changed what the
  document produces preserved nothing, so there is nothing to say two spans are
  the same thing — and recording it anyway would put a false fact into a record
  that cannot be recomputed.
- **Only ranges byte-precise on BOTH sides produce an entry.** A synthetic
  range on either side means there is nothing to correspond, and inventing one
  would be the forgeable middle this design deleted when it removed element ids.
- **A span that did not move records nothing.** "This span is itself" is not a
  fact worth a line in a record.
- **A split span corresponds only where it corresponds.** One baseline block
  that became two records two correspondences, each over its own half — not
  the whole to the whole, which the outputs do not support.
- **The baseline's lineage is captured at `begin`**, when the working tree IS
  the baseline. Storing only the text and re-weaving later would need the
  siblings it reads — pastes, upstream edges — as they were then.
- **Every entry says how it was captured and where.** `precision: byte`,
  `site: refactor`. A query composing several hops reports the weakest link.
- **Both ends are provisional**, because both are the working tree, which is
  above the publication floor by definition — so the address they are keyed on
  can still be replaced by a re-emission.
- **No continuity, no journal.** The whole feature rides one switch: an earlier
  design made the overlay opt-in and the bookkeeping mandatory, which taxed
  every commit to feed a feature most people never turn on.
