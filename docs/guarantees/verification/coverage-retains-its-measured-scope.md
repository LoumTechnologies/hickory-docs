# Coverage retains its measured scope

Given collector evidence from automated, human, or AI-driven testing, importing
or comparing it preserves the measured executable denominator, collector data,
source identity and historical metadata. Missing data is unknown rather than
zero. Test success, assertion quality and workflow verification are separate.

Line comparisons require identical source hashes, collector/version,
instrumentation/configuration, scope, report semantics and executable locations.
Branch comparisons additionally require identifiable branch contributions.
Overlapping labels never add percentages: comparisons use sets of locations.
Aggregate imports cannot establish test attribution. Cobertura's aggregate
branch fractions remain in the original report; they cannot establish which
branch was unique to a group.

- `crates/hickory-cli/src/coverage` is the shared UI/MCP/built-in-agent service.

  normalized within the workspace. Report imports never acquire current hashes
  implicitly. A bounded `locations` read exposes group attribution without

- `coverage/mapping.rs` uses `hick_dap::Mapping` and LSP virtual files without
  starting a debugger. Both document and generated bytes must match before a
  source location is recorded. `apps/web/src/coverage/gutter.ts` fingerprints
  the actual buffer before displaying marks and clears them on edits.
- Browser manual collection uses CDP to read Istanbul counters. Baseline
  subtraction prevents earlier activity becoming session evidence; document
  time-origin and counter-reset guards reject reloads. Checkpoints are cumulative
  from session start, not independent workflow-step contributions.
- Native manual profiles launch explicitly configured instrumented apps. Stop
  signals the process group on Unix and then exports the collector report.
  Live checkpoints require collector support. Manual verdicts are separate
  declarations and do not alter coverage.
- Assumptions: project-owned commands and instrumented applications run with
  normal local permissions; no execution sandbox is claimed. Coverage reports
  can only describe included instrumentation. Paths from other machines require
  remapping before import. C# VSTest collection supports a single distinct target
  report; multiple target reports require separate imports. Actual source
  snapshots omit ignored/runtime/large files; absent measured hashes make source
  identity unknown and comparisons unavailable.
