## Latest authoritative correction: do not teach the predictor the answer

The user's no-copying requirement supersedes earlier issue text permitting an
agent to reveal actual values after recording an observation. Agents must not
receive the held-out target answer through explicit reveal, automatic variables,
watches, evaluation, captures, stdout/stderr/errors, cached transcripts, reports,
publication or context delivery. Recording disclosure is not permission to leak.

The ledger now rejects agent and host-tool reveal requests. Human inspection is
separately recorded; adapters must isolate that evidence from predictor context.
Replacement expectations cannot earn promotion even without a recorded reveal.
Already revealed state remains context; it cannot certify an independent first
prediction. Debugging/repair remains possible while target answers stay withheld.
Exposed targets need honest provenance and fresh held-out evidence to assess new
understanding. This is a managed-interface assurance boundary, not a claim about
unrestricted shell execution or provider internals.

Implemented:

- `hick-literate::prediction::run_output` binds a host-sealed output target and
  exact source bytes before dispatching the existing live pipeline. It withholds
  files/stdout/stderr/errors/expectation diagnostics from its result and accepts
  no stream/cache hooks. Unsupported document families refuse before execution;
  execution/decode failure stays Unknown. Existing runner expectation failure
  cannot be overridden by a matching prediction and requirement.
- `Ledger::admit_target` provides an atomic durable dispatch claim. Concurrent
  request retries and restarted requests observe the existing attempt without
  executing again. Evidence/transport failures become Unknown while retaining the
  unresolved dispatch claim; only a late valid result or authoritative host stop
  confirmation can settle it. Independent execution rejection is retained atomically with
  the private observation and cannot be overwritten by a later successful check.
- `prediction::debugger::run` reuses hick:capture parsing, Mapping and DAP watch
  evaluation for an initial Python expression at a selected hit. It binds the
  root source revision and exact source-line byte range, expression, expected
  top-frame function, actual frame/thread, generated source/line and breakpoint
  confirmation. Missing/moved/unbound hits, mixed threads, wrong source/frame,
  unsupported values and evaluation errors stay non-passing. Private capture
  terminates at its selected bound rather than continuing through unlimited hits.
- `capture::run_private`, private Session startup and private Adapter transports
  suppress build/adapter-message logs and inherited process stderr/TCP stdout.
  Attached and multiplexed adapter sessions refuse private startup. Ordinary
  capture startup still follows its original path.
- Hosts may opt an EditSession into `require_verified_publication()`. Primary and
  upstream generated outputs remain in memory until the whole verification scope
  passes; changed source bytes/closure, uncaptured dependencies and unavailable/
  stale evidence refuse publication. Failed runs do not overwrite/create outputs
  or refresh the session with their runtime products. Default sessions retain
  ordinary failure-output publication. The native tree writer now supplies path/
  symlink preflight for both project and ordinary generated outputs.
- A strengthened upstream witness found earlier executor transcripts entering the
  primary document's weave. `run_transcripts::Scope` now excludes prior invocations
  from final weaving and stdin transcript reads. It requires one pipeline caller
  per executor and does not reset container files/processes.
