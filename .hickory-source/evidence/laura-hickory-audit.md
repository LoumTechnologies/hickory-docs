# Audit a real Android checkout in Hickory

This run follows a security and maintainability review of Laura-app (FloJo) through Hickory. The reader is an engineer who works with a coding agent and needs an independently checkable finding before editing unfamiliar code. The first useful result is a source-linked finding with enough evidence to review and hand off. Laura-app was at Git commit `89b72ef` with existing tracked and untracked changes. The initial audit examined that working tree. Laura-app commit `9639fa1` later corrected the HTML tag emission.

## What the engineer could do

1. From Laura-app, run `../hickory-docs/target/debug/hick open project.md`. The installed macOS editor showed the requested audit desk and its containing folder.
2. The audit desk said to start with its architecture diagram. A blank rectangle occupied the diagram's place. The right-gutter source toggle revealed JSON and toggled back. The fallback investigation table showed clipped link syntax in editable spreadsheet cells.
3. Expand **docs → literate**, then open **03-export.md**. The Kotlin fragments and explanation were readable. The ordinary Markdown source link still showed its relative URL. The modifier-click attempt did not navigate. The tree also opened **audit.md** and showed the prior review.
4. Use `hick search --top-k 6 'renderCard escapeHtml tag media'` from the working tree. Results included both the reading and the ordinary Kotlin source, with path and line ranges. `hick doc read-output docs/literate/03-export.md --path app/flojo/util/HtmlExporter.kt --lineage` rendered the reconstructed output with line hashes and source provenance. Some returned matches were generic CSS or overlapping excerpts.
5. Read the ordinary Kotlin to confirm the finding and its caller. The review could establish that journal tag strings flowed unescaped into exported HTML, with no browser execution required. For persistence, the ordinary source and the reading each showed that undecodable records are dropped from the index used to rewrite monthly files.

Four tree actions opened the two readings after the attempted diagram route. The trace used two Hickory CLI commands after the window opened. A developer can reach the first useful result by going straight to **docs → literate → 03-export.md**, but the audit desk points to the diagram first. The Mac already had Hickory installed, so discovery, download, install, fresh-account setup and any paid boundary still need a first-time walkthrough.

## Laura-app audit findings

The file-based journal places valuable user data at three boundaries. The device and other authorized tools can change its public files. The timeline turns files and metadata into entries. The exporter takes a filtered view to a browser-readable bundle. Fix the integrity and confidentiality problems at those boundaries before relying on the journal for irreplaceable data.

| Priority | Evidence in the working tree | Correction and proof |
| --- | --- | --- |
| P0 | The initial `HtmlExporter.renderCard` encoded title and content and wrote the tag as raw HTML. Tags are loaded from files and editable in the app. | Fixed at the tag text boundary in Laura-app `9639fa1`. The focused JVM test covers punctuation and a plain tag. Check the full exported page and local media on Android. |
| P0 | `MetadataStorage.loadIndexFromDisk` discards undecodable lines and ignores unknown keys, then `persistMonth` rewrites the month solely from materialized known fields. Duplicate IDs replace earlier values in the map. Ordinary reads may write when timestamps lock. | Make read failures, duplicate keys and unsupported fields visible. Preserve original records or refuse affected writes. Include open, edit, autosave and restore tests against old and damaged data. |
| P0 | `VaultPaths.atomicWrite` uses a fixed temporary name and falls back to in-place overwrite. `MetadataStorage` mutates the index before persistence, reloads under a different monitor and splits read-modify-write. | Use a single transaction authority with durable publication and safe recovery. Keep previous bytes and memory state coherent on cancellation, storage failure and concurrent work. |
| P0 | `VaultRepository` creates entry files and metadata in separate steps and ignores the result of file deletion before removing metadata. Multi-month and rename operations can partially commit. | Define cross-file commit or recovery semantics and defer success until durable completion. Verify interruption at each boundary and recover without orphaning or silently losing the record. |
| P1 | The manifest asks for all-files access, and `VaultPaths` keeps readable journal and export data under public Documents. | Preserve user ownership with an explicitly chosen data location, scope access where feasible and clearly disclose vault/export visibility. Test deny, revoke, restore and uninstall/reinstall. [Android all-files access](https://developer.android.com/training/data-storage/manage-all-files) and [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files). |
| P1 | `allowBackup=true` does not specify the product's actual copy or restore policy. The original notes promise manual backups for the public vault and metadata. | Define what app-owned data, public data and exports do across cloud backup and device transfer. Test restoration of both vault and metadata without assuming standard app-backup scope covers public Documents. [Android Auto Backup](https://developer.android.com/identity/data/autobackup). |
| P1 | `HtmlExporter.export` sanitizes names and copies with overwrite. The card recomputes names from source files instead of using the copy result. | Assign one stable collision-safe export name per asset. Render links only for files successfully published. Check duplicate sanitized names, missing inputs, cancellation and denied storage. Report incomplete exports and preserve valid previous bundles. |
| P1 | `VaultRepository` joins records by filename stem. Separate files can resolve to the same ID, and creation depends on the wall clock. | Keep a durable identity independent of filename and define migration and duplicate reporting. Verify rapid creation, same-stem media, external rename, and stable navigation across process death. |
| P1 | `TagRegistryManager` decodes the whole registry on common paths and writes a read-modify-write without shared concurrency control. | Report damaged registry lines without crashing the timeline. Protect concurrent mutations, preserve unknown data and propagate failures. |
| P1 | `TimestampUtils` uses current time for invalid records. `lockExpiredBoundaries` captures today's offset when locking, which can differ from the boundary's offset across DST. `VaultEntry` and metadata month formatting hold shared formatters. | Validate wall times, define ambiguity policy and preserve the instant at lock. Run DST and travel fixtures with a fixed clock. Prove concurrent formatting and consistent month routing for old and external IDs. |
| P1 | File entries are filtered first by resolved entry instant and then by creation filename time. Broad window selection happens before the custom range and other filters. | Use one explicit filter contract for timeline, calendar and exported entries. Include old-created entries rescheduled into range and both custom bounds, then compare IDs across outputs. |
| P1 | `FloJoApp` runs scan from a UI callback and builds export inputs before dispatching export I/O. Export has no local recovery around the dispatched operation. | Move vault work off the main thread, show bounded progress, handle cancellation and retain the existing view on failure. Measure large-vault responsiveness and revoked permission. |
| P1 | Source includes no app test files or staged release acceptance. Add focused durability, export, lifecycle and process-death tests. |
| P1 | The wrapper URL is pinned to 9.5.0 without a distribution checksum. The local wrapper JAR matches Gradle's published 9.3.0 and 9.3.1 bytes while the download URL selects 9.5.0. | Align the wrapper artifacts with the selected Gradle release and pin its distribution SHA-256. Lock and verify the resolved production dependency graph. [Gradle release checksums](https://gradle.org/release-checksums/). |
| P2 | Current notes and code differ on export folder spelling and timestamp fallbacks. ## Verification scope

The installed macOS app and Simple Browser were walked against the Laura working tree. Laura-app’s `:app:assembleDebug` succeeded using the installed JDK 21 launcher and Gradle’s JDK 25 daemon. APK inspection found all-files access, both legacy storage permissions capped at API 29 and `ACCESS_NETWORK_STATE`. The inspected APK did not declare `INTERNET`. The build did not exercise app behavior. CLI evidence came from the sibling checkout. The active frontend support contract also includes iOS, Android, KDE and Windows. Shared resource checks establish a portion of native rendering. They do not replace installed UI acceptance. A complete platform comparison, release-artifact review, agent-pane audit, download funnel and Android runtime acceptance remain open.

- Laura-app’s reading verifier passed after excluding only `/.hick-cache/` through a temporary Git excludes file. All 45 text outputs reconstructed exactly, eight default-configuration equivalence checks passed and the 46 original paths retained their bytes, kinds and modes. The original source and baseline were left intact.
- Three focused Vitest cases passed. They cover browser graph styling inside the editor’s shadow root, workspace-relative link restrictions and the shared native preview asset. `vitest run src/simple/parity.test.ts -t 'diagram|native graph|graph canvas'` selects just these cases from `apps/web`.
- A focused macOS `WKWebView` probe loaded the actual JSON from Laura-app’s audit desk. The installed resource drew an empty graph. The updated resource drew nine node labels and ten edges without a renderer error. The probe did not exercise the surrounding AppKit editor or its navigation.
- Playwright drove Simple Browser served by a local workspace host. The browser rendered the nine architecture nodes on `project.md`. Opening the audit chapter and double-clicking its HTML boundary node opened `03-export.md` in the real editor. This tests a link that Laura’s top-level diagram lacks.
- Gradle resolved 130 release runtime Maven coordinates. OSV’s batch endpoint returned a result for each coordinate, with one advisory match and no pagination. This checks known Maven advisories for that classpath at the time of the run. Build plugins, platform decoders, release-artifact contents and exploitability remain open. [OSV batch API](https://google.github.io/osv.dev/post-v1-querybatch/).


- The rebuilt Simple Browser followed the export chapter’s **Open authoritative source** label to `app/flojo/util/HtmlExporter.kt` with Command-click. The destination showed the corrected tag encoding after scrolling to the renderer. Plain-click discoverability, keyboard activation and native gestures remain open.
- In the rebuilt Simple Browser, **View → Agent** opened the composer. The focused composer displayed Codex and its default model in the status bar. The outgoing request named `codex-subscription`, left the model override empty, and supplied the exact open `project.md` text to the local workspace request as a live editor snapshot. The fixture returned an error before provider delivery, and Hickory retained the complete prompt. The local snapshot is distinct from the provider-visible projection. [Selected context contract](../guarantees/agent/the-agent-sees-the-open-editors/contract.md).
- Laura-app commit `9639fa1` routes journal tags through the same existing text encoder as titles and content. One focused Gradle JVM test invoked the real card renderer with a label containing angle brackets, an ampersand and quotes, then checked the entity-encoded text and an unchanged plain tag. The test fixture lived outside Laura’s checkout and ran on its current local Gradle scaffold. This did not exercise Android storage or full export from the device. The original literate reading is a pre-fix capture and intentionally differs at the corrected line.
