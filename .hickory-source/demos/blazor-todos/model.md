# Give each account its own todo rows

The [Blazor scaffold](scaffold.md) already supplies a user ID, a SQLite
connection and an EF Core migration history. Add a todo entity whose
`OwnerId` is required and assigned by the server. The separate
`Editable(true)` marker opts a property into UI generation. A key or owner
property has no such marker.

<demo:file id="todo-entity" path="examples/projects/blazor-todos/app/Models/TodoItem.cs">
using System.ComponentModel.DataAnnotations;

namespace HickoryTodos.Models;

public sealed class TodoItem
{
    public int Id { get; set; }
    public string OwnerId { get; set; } = string.Empty;

    [Editable(true), Required, StringLength(120)]
    public string Title { get; set; } = string.Empty;

    [Editable(true)]
    public bool Completed { get; set; }
}
</demo:file>

## Extend the scaffold context and keep its migration history

The relationship ties every row to an Identity user. Deleting an account
also removes its rows. Replace the scoped context registration with a
factory. Identity can still resolve its scoped context, while an interactive
page opens a fresh context for each operation and disposes it when done.

`dotnet ef migrations add AddTodos --output-dir Data/Migrations` after adding
the model. The snapshot change is included in the context patch above.
The startup path from the scaffold chapter applies both migrations to a
fresh database or just this migration to a database that already has Identity.
