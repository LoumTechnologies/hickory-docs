# Keep the comparison frontends equivalent within their declared slice

For maintainers extending the new frontends without silently changing the comparison.

Given a reachable existing Hickory engine, each frontend exposes the same four pane kinds: files, text document, workspace agent and terminal. Plain and literate source open as text. Generated outputs open read-only in this slice. File and pane commands remain in menus or tab strips; editor content has no permanent feature toolbar.

Opening text does not wait for rendering, provenance, debugging or language services. Pane splitting, resizing and moving retain document buffer identities and unsent agent messages. Drag a tab to the outer twenty percent of pane content to split left, right, above or below; the shaded half previews its destination. The middle appends the dragged tab to that existing group and activates it without adding a split. Corners select left/right. Center drops preview the whole target pane. A successful drop moves the existing tab into a fresh equal split and focuses it; any empty group closes automatically and its surviving sibling fills the freed rectangle. Closing the last tab in a group does the same. If all tabs are closed, one empty root remains available. An explicit Split command may create a temporary empty destination until the next close or move. Stale or unknown payloads do not create splits. Drag a tab onto another tab to insert before it, or onto unused strip space to append, within a group or across panes. Drag indicators overlay tab edges without resizing the strip. Self-drops and obsolete source/destination identities leave membership unchanged. Both drag and menu movement are available. Dirty document tabs refuse to close.

A plain save includes its original content hash. A literate save includes its original source as both room and disk expectation. Failed saves retain edits. A successful reply marks only the submitted snapshot saved; typing during that request remains dirty. Save and agent mutations are never automatically replayed by these frontends after transport failure.

Every text document offers **Edit → Find and replace** and Cmd/Ctrl-F. Search supports next/previous navigation, case sensitivity, regex mode and replace-one/all; regex replacements accept `$1`, `$&` and `$$`. Controls float above text without resizing it. Native matching runs in the background and uses UTF-16 source positions. Source, query and permission checks reject stale replacements. Replace-all is one undo operation; read-only text remains searchable. Native searches skip zero-width matches and refuse replacement when more than 10,000 nonempty matches would truncate the result. Advanced regex syntax follows the platform's engine.

Every text document offers Fold/Unfold on indented logical blocks through its right-hand line-action menu. Tabs count as four indentation columns; blank lines do not create fold headers. Folds hide the body while retaining its original source bytes and logical line numbers. Nested folds and read-only folding are supported. Native edits retire fold positions; an edit touching hidden text first reveals it without applying that edit. Navigation to a hidden native debugger location unfolds the document. Browser folding also uses available server ranges and the standard CodeMirror fold shortcuts. This slice does not claim native syntax-aware folding for unindented blocks.

Every text document has a left line-number gutter, starting at 1, including empty documents and the empty line after a final newline. Numbers follow logical lines through edits, scrolling and wrapping; wrapped continuations have no additional number. The number gutter is separate from the right contextual-action rail.

Every document has an interactive fixed-width minimap. Language services attach independently after readable text. Browser, Apple and Android use the existing engine LSP channel for semantic colors and completions. Native **Edit → Language tools** (Ctrl-Space) exposes diagnostics, hover, signatures and inlay information. Source, selection and connection guards reject obsolete replies. Native diagnostics without a matching version remain readable messages without navigation positions. Unsupported capabilities fail independently. Native completions currently exclude snippets and additional edits; cross-file navigation, rename and code actions remain outside this slice.

All editors support multiple selections. Browser uses its established rectangular and multi-cursor commands. Native Find offers Select all matches; Edit offers column selection and additional cursors above/below, bounded to 256 selections. Apple broadcasts ordinary typing through one native undo transaction. Android broadcasts physical-keyboard typing and offers explicit Apply to selections for touch input. IME composition retires secondary native selections, preserving normal platform composition.

Inline presentation preserves editable source. Browser reuses the existing rich table, equation and recorded-output widgets inside the editor. Native editors style Markdown source and attach floating table/CSV cell editors, local KaTeX equation editors and recorded execution output to source lines. Applying a contextual edit verifies its source snapshot and uses native undo. Native source remains visible; this is not full native WYSIWYG replacement. Formatting scans are bounded to 200,000 UTF-16 units; larger text stays readable. Recorded outputs require an exact document/source hash and are never replayed automatically. Conversation Markdown formatting remains browser-only.

All simple frontends attach the existing engine DAP debugger inline for plain files and Hickory file blocks. Launch icons occupy a fixed right column; active step, continue, stop, stack, watch and evaluation controls follow the paused line. Sessions survive tab switching and movement. Unsaved text refuses launch and hides positional values until saved. The browser reuses the existing editor debugger; Apple shares a SwiftUI rail across macOS and iOS; Android uses a Compose rail. Native controllers retain one active workspace session. Native line actions open a floating grid with launch, breakpoint, continue, step, stop, stack, condition, evaluate and watch controls; adapter capabilities gate optional actions. Native locals describe the stopped top frame; selecting a caller clears those locals and evaluates watches in that selected frame. Parsed file-block targets and source mappings come from the engine.

These are the initial frontend requirements, not full parity with the old frontend. Full native WYSIWYG, capability menus, provenance, additional agent backends, settings, durable layout and crash recovery are outside this slice. A framework build or shared model fixture cannot establish native input-method, accessibility, gesture or latency equivalence.
