# Installed IDE drive — 2026-10-13

Audience: the Hickory maintainer reviewing an installed-app usability pass for an
engineer who wants executable notes, editable generated code and an agent in one
IDE. The agent-output-owner persona is an unvalidated hypothesis; this run does
not establish demand, conversion, or willingness to pay.

The pass drove `/Applications/Hickory Docs.app` on macOS and real-engine browser
flows in disposable projects. Existing repository edits were preserved. No paid
model turn was required by the regression tests.

## Findings and fixes

| Priority | Where | Expected | Observed | Implemented correction |
| --- | --- | --- | --- | --- |
| P1 | Settings → Back | Return to the same working editors | Existing project tabs were replaced by a recovered unnamed draft | Retain the mounted workspace; restore its route, editor selection and title; apply preferences live |
| P1 | Search from Agent | Open and center the chosen note | The note appeared as a tab while Agent remained centered | Track the focused tab as well as its pane; Restore also restores the command target |
| P1 | Startup cell | Clicking the offered action makes progress | Run on an unnamed cell did nothing; the result said “cell not yet known to the server” | The rail opens Save first and explains the prerequisite; the starter gives Save → Run → Test |
| P1 | Install Python debugger | Install and retry from the IDE | A folder with spaces made `uv` reject the word “walkthrough” as an extra argument | Shell-quote the shared prefix, including paths with apostrophes and shell punctuation |
| P1 | Python stack frames | Stop and show the document source line | Four real debugpy tests stopped but lost their document coordinates through `/var` vs `/private/var` | Resolve adapter path aliases against canonical map entries |
| P2 | Command discovery | Find Run and Test by name | Only workspace-level commands were available | Expose the owning document's existing Run/Test actions with its path |
| P2 | Fast palette typing | Enter acts only on the current query | Old results remained selectable while the new request resolved (confirmed in code and regression test) | Hide stale results, show pending search, scroll keyboard selection into view and announce it |
| P2 | Agent entry | Start typing a response immediately | Focus remained outside the response editor | Start the visible editor at the draft; Write a response returns to it without rewriting session bytes |

Typed confusion quotes, in the engineer's voice: “Where did my tabs go?”, “Why
am I still looking at the agent?”, “You offered Run—why did nothing happen?”,
“Why should a space in my folder stop debugger setup?”, and “The breakpoint
worked; why can't the IDE show me its source?” No abandonment rate is inferred.

## Verification

- `just test-web`: 221 files / 2,098 tests passed before the final unnamed-cell
  regression and focus-key adjustment. Subsequent affected paths were tested
  with `just test-workflow` (8 files / 92 tests) and `just test-spatial`
  (5 files / 42 tests).
- `just test-workflow-ui`: real-engine checks cover document Run/Test, initial
  agent typing, return to the draft, Settings editor identity/selection/tabs,
  Save adoption, unnamed-cell Save then Run, search centering and Restore.
- `just test-debugger-paths`: all 10 real debugpy sessions and both project
  mapping tests passed after the alias fix.
- The shared confined installer passed its offline path regression with a
  directory containing spaces, an apostrophe and shell punctuation. It still
  uses the same sandbox and catalogue.
- Native drive observed Save's OS dialog, creation of the note and generated
  Python file, the missing-adapter offer, its failed install diagnostics, agent
  draft focus, folder attachment and retained tabs through Settings.

The initial native multi-draft Save did not show a dialog. A later Save after
recovery succeeded. Dedicated browser checks exercise Save adoption and selection
among multiple unnamed notes; this report does not infer a distinct save-layer
cause from that initial symptom.

## Boundaries and remaining design work

- Agent history is intentionally still a literate document. Its context and
  tool bookkeeping can feel visually heavy in long conversations; a separate
  reading-density pass should preserve native folds and provenance rather than
  discard those records.
- The experimental Python agent still reports checks as unrun and requires
  document-edit review. These were existing product boundaries, not broadened.
- Native agent filesystem integration requires the signed extension build;
  the local ad-hoc build explains that limitation.
- No live provider sign-in or paid-model quality claim is made. Deterministic
  agent tests exercise the UI and real confinement, not model intelligence.
- This is macOS evidence. Other desktop platforms, compiled-language debug
  toolchains, fleet connections and large-project indexing were not re-audited.

The next-action path is: save an ordinary note, run its cell, test its expectation,
open a generated file, return to its explanation, and ask the agent with the
current editor context visible. Settings and navigation should preserve that
work instead of restarting the experience.
