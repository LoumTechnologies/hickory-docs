# Review the agent-first deadline investigation

Audience: engineers evaluating the issue 72 workflow before installing it.

The customer needs a 100ms deadline **including retries**. The seeded proposal
gives each attempt another 100ms. Two 80ms attempts expose the mistake. Delegate
investigation, setup, debugging and focused checks; the human interprets evidence,
sets the criterion, approves edits and resolves the review thread.

Open **AI engineer tour** in a development build and explicitly create an isolated
practice repository. Copy the coach’s investigation task into the normal
workspace conversation. Choose your provider and explicitly Send. Copying a task
sends no request. Use the normal source, environment, debugger and review controls.

The coach reads retained host evidence: correlated Python provider delivery,
source-bound execution receipts, bound/paused debugger observations, successful
reviewed edits and the actual review thread. Reopening reconciles the saved step
against that evidence. Skip leaves a step unestablished. ACP shares the UI broker,
but its opaque provider internals do not satisfy the Python delivery witness.

The homepage browser example uses recorded proposals and live browser execution.
The recording loader accepts only selected, hash-reviewed media through the
existing publication pipeline. An absent recording remains explicitly unavailable.
A recording’s captured revision and a publication’s tested revision are separate.

Universal UI parity, a current packaged native/provider run, actual footage and a
matching deployed-build witness remain acceptance work. Existing prereleases may
predate these changes. See the [parity inventory](ui-action-parity.md) and
[capture procedure](engineer-tour-video.md).

For the optional strict version, create a **private prediction practice** instead
of using the ordinary workspace. It adds initial/future-stop sealing, withheld
target values, retained failure, human-reviewed correction, unchanged-expectation
promotion and explicit End. See the [private capture procedure](engineer-tour-video.md#record-the-optional-private-prediction-workflow).
The private ACP adapter has a separate managed profile; ordinary ACP settings do
not grant private access. Neither path claims confinement of provider internals.

For a focused attached-provider development witness, with the configured desktop
provider key store and installed Python runtime, run from the repository root:

```sh
HICKORY_KEEP_UI_WITNESS=1 scripts/test-python-agent-ui.sh --live-provider
```

This explicitly makes paid provider calls in a disposable seeded repository. The
model investigates an actual failed source-bound check, proposes one exact patch,
and requests focused verification after the test driver reviews that patch in
the normal UI. Test-driver acceptance is labelled; it is not human judgment.
Retained sessions and browser footage are private diagnostics, not automatically
selected publication assets. Without `--live-provider`, the script uses scripted
model responses. Neither mode is a packaged desktop-shell or deployed witness.

## Try your own browser inputs

In the browser tour, choose **Try input-changing prediction practice**. It replaces
the other demos with the same coach's prediction branch. A direct development
entry is `site.html?predictionPractice=1`; a deployed URL is acceptance evidence
only after its build revision is verified.

Change the whole-millisecond durations/budget, inspect source, enter a prediction
and rationale, Seal, then Run. A real interpreter checks the requirement plus
short/empty cases. Continue from a retained counterexample to the recorded
correction; seal the unchanged original prediction and run again. Replacing the
prediction cannot advance the correction. Proposals/corrections remain recorded
examples; execution is live, with no provider or API key involved.

Answers stay out of this managed agent window. Human inspection opens separately;
it does not authorize copying actuals back into predictor context. Valid question
inputs restore after reload, while predictions/rationales must be re-entered.
Select a scenario with a seal before recovering interrupted attempts. Recovery
requires an exclusive runtime lease, preserves interruption/Unknown history and
never replays a request. Closing the coach does not reopen ordinary agent controls.

This browser-local history cannot authenticate prior exposure or the entire
runtime environment. It remains Unknown and cannot certify a native run or grant
promotion. Use fresh native private practice for retained debugger/future-stop
predictions and authoritative host checks. Browser internals, extensions, devtools
and unrestricted external clients are outside the typed broker boundary.
