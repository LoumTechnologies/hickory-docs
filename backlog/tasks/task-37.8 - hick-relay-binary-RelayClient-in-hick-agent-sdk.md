## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Build the cloud relay service that enables web remote control from any device without port forwarding. The agent connects outbound to the relay; remote browsers connect to the same relay session. The relay forwards bytes in both directions without parsing them.

## What to build

### New binary: `hick-agent/crates/hick-relay`

A standalone axum web server binary deployed on a Hickory domain. It has two WebSocket endpoints:

- `GET /agent/:session_id` — the running agent connects here as a WebSocket client
- `GET /session/:session_id` — remote browsers connect here as WebSocket clients
- `GET /session/:session_id` (HTTP) — serves the same React SPA as the local server (so the browser gets the full UI)

The relay:
- Maintains a registry of active sessions (in-memory, `HashMap<SessionId, AgentHandle>`)
- Forwards all WebSocket frames from the agent connection to all browser connections for the same session ID
- Forwards all WebSocket frames from any browser connection back to the agent connection
- Does not parse, validate, or transform any messages — pure byte forwarding
- Drops browser connections when the agent disconnects and cleans up the session

**Session ID**: a random UUID-v4 generated by the agent at startup. Only the person who started the agent sees it (printed to stdout). There is no server-side registration or authentication — possession of the UUID is the credential.

### Infrastructure

- Provision the relay server using Terraform (consistent with the project's infra approach)
- Target: a small VM or container (e.g., fly.io, Railway, or a VPS) on a `relay.hickory.dev` subdomain
- TLS termination via the hosting provider's proxy (the relay binary itself runs plain HTTP/WS)
- The Terraform config lives in `infra/relay/`

### `RelayClient` in `hick-agent-sdk`

```rust
pub struct RelayClient { ... }

impl RelayClient {
    /// Connect to the relay and begin forwarding events.
    /// `relay_url` is e.g. "wss://relay.hickory.dev/agent/<session_id>".
    pub async fn connect(
        relay_url: &str,
        event_rx: broadcast::Receiver<UiEvent>,
        cmd_tx: mpsc::UnboundedSender<UiCommand>,
    ) -> anyhow::Result<Self>;

    /// The shareable session URL for the remote browser.
    pub fn session_url(&self) -> &str;
}
```

### Binary crate integration

When `HICK_RELAY_URL` env var is set (or relay is configured in `.hick/relay.toml`):
1. Generate a session UUID
2. Connect `RelayClient` to `wss://<relay-url>/agent/<session-uuid>`
3. Print to stdout: `Remote control: https://relay.hickory.dev/session/<session-uuid>`
4. The relay connection runs alongside the local web server — both surfaces are active simultaneously

## Constraints

- The relay must handle agent reconnects gracefully (agent drops and reconnects within 30s — preserve the session, reconnect browser clients)
- The relay binary must be stateless between restarts (no persistence — active sessions are lost on restart, which is acceptable)
- `RelayClient` must be behind the `relay` Cargo feature flag in `hick-agent-sdk`
- The relay binary itself has no knowledge of `UiEvent` or `UiCommand` types
