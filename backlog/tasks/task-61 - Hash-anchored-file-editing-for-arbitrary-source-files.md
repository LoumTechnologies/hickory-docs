## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement hash-anchored editing for arbitrary source files (Rust, Python, TypeScript, configs, etc.) that are not generated by the hick pipeline. This is the complement to the existing `HickEditFormat` (which handles `.hick` pipeline sources via provenance). For non-pipeline files the agent has no provenance map, so it needs a different safe-edit mechanism.

The oh-my-pi approach: every line in a file gets a short content-hash anchor when the agent reads it. The LLM references anchors instead of line numbers when specifying edits. If the file was modified between read and edit (by another tool, a concurrent process, or the agent's own prior turn), the anchors diverge and the edit fails explicitly with a clear error rather than silently patching the wrong location. This eliminates the "line drift" failure mode that causes the agent to corrupt files after its own edits shift line numbers.

New crate: `hick-agent-file-edit` (or add to `hick-agent-sdk`). Expose as agent tools: `read_file_anchored` and `edit_file_anchored`.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 read_file_anchored(path) returns file content with a short hash prefix on each line (e.g. `a3f2| fn main() {`); hashes are stable for identical content
- [ ] #2 edit_file_anchored(path, anchor, new_lines) locates the line whose hash matches `anchor`, replaces it (and optionally a range), and writes atomically
- [ ] #3 If the anchor is not found in the current file content the edit returns a typed StaleAnchor error and makes no change
- [ ] #4 A multi-line replace variant accepts anchor_start + anchor_end and replaces the inclusive range
- [ ] #5 Atomic write: new content goes to a .tmp file then is renamed into place
- [ ] #6 An integration test demonstrates: read → anchored edit → re-read shows change; a second edit with the original (now stale) anchor returns StaleAnchor without modifying the file
- [ ] #7 The tool is registered in the agent and appears in the system prompt with usage instructions
- [ ] #8 Works on binary-safe UTF-8 files; returns a clear error for non-UTF-8
