# Build Hickory Docs

Hickory Docs is an IDE for programs whose source is a literate Markdown document.
Engineers explain a decision, construct real files beside that explanation, run
selected commands and trace generated bytes back to their authored source. In this
tutorial, we will build that IDE with its own language: start a workspace, construct
exact files, retain scaffolded output, then add execution, editing and persistence.

## Start with Cargo, then compose the workspace

We begin with Cargo's package scaffold:

```sh
cargo init --lib --name hickory_docs --vcs none --edition 2024 seed
mkdir -p out
cp seed/Cargo.toml out/Cargo.toml
```

The [workspace chapter](.hickory-source/support/files/Cargo.toml.md) retains that
executed command, its inline captured manifest and the authored patch that turns
it into this repository's `Cargo.toml`. Only the manifest enters the output volume;
Cargo's temporary library is not part of Hickory. Hickory folds the captured file
by default. Reconstruction replays those bytes and applies the patch without
running the scaffolder again.

<book:include file=".hickory-source/support/files/Cargo.toml.md" />

A clone already contains the generated files. Build the command-line tool to work
on this document with the implementation we are describing:

```sh
cargo build --locked -p hickory-cli --bin hick
./target/debug/hick project verify project.md
```

Verification reads the complete declared source and compares existing outputs;
it does not execute the retained scaffolder. For changes, edit the owning Markdown,
then regenerate and check agreement:

```sh
python3 hickory-dogfood/tools/behavior.py generate
python3 hickory-dogfood/tools/behavior.py check
python3 hickory-dogfood/tools/behavior.py audit
```

The Python commands maintain this repository's dogfooding records. Other projects
use the product's `hick project` commands. The [maintainer workflow](docs/developers/literate-workflow.md)
explains bootstrap, staged verification and focused checks.

## Construct the language and its application

Follow these steps to build the core of Hickory. Each starts from what we have,
adds the next needed behavior with actual maintained implementation, and explains
the assertion that checks it. Requirements appear when they motivate a decision.
The complete source graph builds together; isolated chapters are teaching steps,
not separately compiling releases.

1. [Construct an exact project tree](.hickory-source/01-language.md): portable entries, explicit dependencies and pure evaluation.
2. [Capture scaffolds and author patches](.hickory-source/02-scaffolds.md): immutable inline bases, ingestion and editor safety.
3. [Add native execution](.hickory-source/03-native.md): source preparation, execution boundaries and native replay.
4. [Edit source and generated files](.hickory-source/04-editing.md): document composition, provenance and reverse editing.
5. [Save and collaborate](.hickory-source/05-saving.md): shared persistence and native serving.
6. [Assemble the application and its checks](.hickory-source/06-application.md): CLI dispatch, browser and desktop hosts, CI selection and release constraints.
