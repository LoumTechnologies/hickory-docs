# Review the reset decisions before changing behavior

For: Hickory's product owner and maintainers checking whether the new organization
preserves stakeholder intent and the captured program.

The reset now assigns every behavior page a requirement disposition. Read the
current guarantee for the promise, its review page for implementation and tests,
and the preserved original for earlier positions and verification history.
The original repository and generated program bytes remain unchanged.

## What changed

| Disposition | Pages | What it means |
|---|---:|---|

The old blanket “315 migrated contracts pending” status is gone. That change
records explicit editorial dispositions; it does not turn unreviewed code into
verified behavior.

The decisions resolve several concrete conflicts:

- Model-visible input follows selected reading scope. Open edit snapshots do not
  automatically become full model context.
- Python owns the current built-in conversation loop. The removed Rust loop's
  evidence does not certify the replacement.
- Snippet confinement and registered host execution are different authorities.
  Removing a direct shell tool does not make host terminal effects impossible.
- Debugging uses exact displayed source and valid atomic project endpoints.
  The historical global-selector interpretation is not the current rule.
- JavaScript/TypeScript discovery includes multi-session support. The older
  unavailable statement is retired; React components and Ruby have distinct limits.
- Manual Unstable publication follows the explicit October 25 requirement, which
  removed the earlier green-CI-only gate. No publication was performed here.
- Explicit discard stays discarded even when a recovery write was in flight.
  Periodic recovery is separate from an acknowledged save.
- Generated saves use the last acknowledged baseline and serialize overlapping
  saves. Newer local edits remain pending when an earlier save settles.
- Current header menus replace the earlier dedicated document toolbar row.

The complete authored decisions are in `decisions.json`. Current requirements
remain in the Markdown source; the JSON records the migration interpretation.

## What was preserved and simplified

The paragraph ledger partitions every original contract file into exact byte
ranges, with hashes and destinations: 3,715 ranges across 326 contracts. The ledger preserves contract text, explanatory context and follow-up notes;
its labels describe retention rather than semantic classification.
Later notes are retained for review; a mechanical partition cannot determine
whether every consequential assumption was found or every meaning preserved.
The eight audit/evidence files have their own history disposition and are outside
that contract-paragraph ledger.

277 repeated opening paragraphs were removed from detail pages because the
current overview already states them. Large requirements use small linked detail
pages. Dated reviews stay in the preserved originals and execution receipts,
rather than accumulating under the current promise.

384 abbreviated citations now resolve uniquely to captured files. Fifteen short
Rust forwarding modules lead to their actual re-exported implementation. These
are navigation improvements, not new evidence of semantic coverage. The map still
lists 562 implementation files without a direct requirement reference; source is
not silently excluded because that association is missing.

The preceding agent-authored drafts are retained in `prior-drafts.json.gz`.
An intermediate shortening pass omitted the eight earlier summaries' explicit
examples and evidence limits. Those were restored before final validation; no
program bytes were affected. Source equality alone would not have detected that
editorial omission.

Requirement retention, LLM implementation review, executed checks and human

Follow-up paragraphs include historical check details and possible additional

## Assumptions and falsifiers

The originating request was to integrate stakeholder promises, implementation and
tests in an isolated rewrite, preserving source bytes. The chosen interpretation
keeps the captured working tree as the behavioral baseline and reorganizes its
maintained Markdown. Changing the implementation to make an outdated promise
true was rejected for this phase because it would change that baseline.

Exact original identities are in `baseline.json`; current referenced identities
and statuses are in `behavior-map.json`. A missing or differing generated file
falsifies source preservation. A missing paragraph interval falsifies accounting.
A passing narrow test does not falsify an untested counterexample elsewhere.
Human intent can supersede any retained requirement through a recorded decision.
